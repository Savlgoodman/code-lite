## 2. 产品概述

code-lite 是一款桌面端多 Agent 工作台。产品通过统一的 UI、会话协议、权限策略和远程同步能力，把 Codex、Claude Code、opencode 等 coding agent 接入到同一个工作流中，帮助用户完成代码开发、仓库理解、脚本编写、文档整理、自动化排障和其他可由 agent 协助完成的任务。

产品不是某一个 SDK 的外壳，而是一个可切换、可扩展、可观察的 Agent Runtime 宿主。用户可以选择适合当前任务的 agent，也可以在后续阶段把不同 agent 用于不同子任务，例如让 Codex 负责代码修改，让 Claude Code 负责方案审阅，让 opencode 负责本地开源模型或自定义模型流程。

code-lite 还需要支持远程连接和远程同步观看：用户可以从另一台设备连接到正在运行的工作台，实时查看 agent 输出、工具调用、文件变更、审批请求和任务状态，并在授权后参与控制或审批。

## 3. 产品目标

### 3.1 核心目标

1. 建立以 ACP 为主线的多 Agent 接入层，优先接入 Codex、Claude Code 和 opencode。
2. 为编码任务提供稳定的对话、上下文、文件变更、命令执行和审批体验。
3. 支持非编码任务，例如文档生成、日志分析、数据整理、方案规划和本地自动化。
4. 支持远程连接，让用户可以在另一台设备上同步观看任务进展。
5. 支持远程协作控制，在授权范围内允许远端用户发送消息、取消任务或处理审批。
6. 保留可审计、可回放的任务记录，方便用户追踪 agent 做过什么。

### 3.2 非目标

1. MVP 不追求同时完整实现所有 agent 的全部能力。
2. MVP 不做云端托管 IDE，也不替代完整的代码编辑器。
3. MVP 不默认上传仓库源码、API Key 或本地隐私数据。
4. MVP 不承诺远程多人实时编辑同一文件。
5. MVP 不开放未经确认的远程系统级命令执行。

## 4. 目标用户

| 用户类型 | 典型诉求 |
| --- | --- |
| 独立开发者 | 在本地仓库中快速完成代码修改、测试、重构和文档更新 |
| 小团队工程师 | 统一管理多种 coding agent，减少切换工具和配置成本 |
| 技术负责人 | 远程同步观看 agent 执行过程，审阅方案和关键变更 |
| 远程协作者 | 通过连接码或授权链接查看任务进展，并在必要时参与审批 |
| 高级用户 | 对比 Codex、Claude Code、opencode 在不同任务中的表现 |

## 5. 核心场景

### 5.1 本地编码任务

用户选择一个本地 workspace，输入需求，例如“修复设置页保存失败的问题”。code-lite 将任务交给选定 agent，并实时展示：

1. agent 的思考摘要和执行计划。
2. 读取的文件、运行的命令和工具调用。
3. 文件变更摘要。
4. 测试、构建和静态检查结果。
5. 需要用户确认的高风险操作。

### 5.2 多 Agent 切换

用户可以按任务选择不同 runtime：

| Runtime | 初始定位 |
| --- | --- |
| Codex | 代码仓库理解、代码编辑、测试修复、工程化任务 |
| Claude Code | 长上下文代码分析、方案推演、审阅和复杂重构协助 |
| opencode | 开源 agent 工作流、自定义模型、本地或私有化部署探索 |

不同 runtime 的私有配置不得污染统一业务协议。UI、会话存储、远程同步和审批系统只依赖统一的 Agent Adapter 接口。当前 coding agent 主线为 `AcpAgentAdapter + RuntimeDescriptor`，Codex、Claude Code 和 opencode 的差异应沉到 descriptor、命令、环境变量、预检和能力说明中。

### 5.3 远程同步观看

用户在主设备启动任务后，可以生成一次性连接码或局域网访问地址。远端设备连接后可以同步观看：

1. 当前会话消息流。
2. agent 运行状态。
3. 工具调用和命令输出摘要。
4. 文件变更列表。
5. 待审批请求。
6. 最终总结和验证结果。

远端默认是只读观看模式。只有主设备明确授权后，远端才可以发送消息、取消任务或处理审批。

### 5.4 通用任务

code-lite 不局限于写代码，也支持：

1. 生成技术文档、发布说明和任务清单。
2. 分析日志、配置文件和错误堆栈。
3. 编写一次性脚本或数据处理流程。
4. 总结仓库结构和模块职责。
5. 规划重构方案或测试策略。

## 6. 功能需求

### 6.1 Agent 工作台

工作台是应用第一屏，直接展示可操作的任务界面，不做营销式首页。

功能要求：

1. 选择 workspace。
2. 选择 agent runtime。
3. 选择模型或使用 runtime 默认模型。
4. 输入任务并启动会话。
5. 实时展示流式输出、工具调用、命令结果和文件变更。
6. 支持取消当前 turn。
7. 支持查看历史会话。
8. 支持复制任务摘要和验证结果。

### 6.2 多 Agent Adapter

后端需要提供统一 adapter 协议，隔离不同 runtime 的差异。coding agent 优先走 ACP 路线：code-lite 作为 ACP client，通过 `codex-acp`、`claude-agent-acp`、`opencode acp` 等 server wrapper 启动或连接具体 runtime。

统一能力至少包含：

1. runtime 描述信息。
2. 可用状态和依赖检查。
3. 流式事件输出。
4. 会话状态管理。
5. 工具调用事件映射。
6. 命令执行和文件变更事件映射。
7. 审批请求映射。
8. 中断和取消。
9. 模型、模式、思考强度等会话能力。
10. runtime 原生配置引用和 code-lite 托管配置边界。

### 6.3 Codex 接入

Codex 是 MVP 第一优先级 runtime，定位为代码仓库任务和真实 ACP 链路验证对象。

需求：

1. 通过 `codex-acp` 和通用 `AcpAgentAdapter` 启动 Codex turn 并流式返回事件。
2. 支持从 ACP `session/new` 读取 modes、models 和 configOptions。
3. 支持将 Codex 文本、工具、命令、文件修改和 token usage 映射为统一事件。
4. 支持中断 turn。
5. 支持把 Codex 原生审批请求映射到 UI。
6. 明确标注 Codex 原生审批不等于产品级完整审批边界。

### 6.4 Claude Code 接入

Claude Code 初期通过 `claude-agent-acp` 接入；如后续需要 native SDK，只能作为补充能力，不作为主线协议。

需求：

1. 通过 runtime descriptor 描述 `claude-agent-acp` 命令、版本、安装状态和 caveats。
2. 将 ACP session updates、permission requests、工具调用、文件变更和错误映射为统一事件。
3. 支持 workspace 参数、会话上下文和 Claude Code 原生配置。
4. 支持取消运行中的任务。
5. 对 skills、commands、settings source 等尚未 smoke 的能力标记为实验性。

### 6.5 opencode 接入

opencode 作为开源 agent runtime 接入方向。

需求：

1. 优先通过 `opencode acp` 接入。
2. 支持通过通用 ACP adapter 和 opencode descriptor 启动任务。
3. 支持映射消息流、工具调用、文件变更和命令输出。
4. 支持与 opencode 原生模型/provider 配置并存。
5. 预留本地模型、私有模型和自定义 provider 场景。

### 6.6 远程连接

远程连接需要提供明确的安全边界。

MVP 需求：

1. 本机生成一次性连接码或访问令牌。
2. 远端连接默认只读。
3. 同步当前会话状态和后续事件。
4. 断线后可重新同步最近事件。
5. 主设备可以撤销连接。
6. 远端身份和权限写入会话审计。

后续增强：

1. 多远端观看者。
2. 远端发送消息。
3. 远端审批。
4. 通过中继服务跨网络连接。
5. 端到端加密和设备信任列表。

### 6.7 审批与安全

所有 runtime 的高风险动作都需要被产品层观察、记录，并在能拦截时进入审批。

风险操作包括：

1. 删除或覆盖大量文件。
2. 修改仓库外文件。
3. 运行安装器、系统设置或权限提升命令。
4. 访问敏感文件，例如私钥、token、`.env`。
5. 推送代码、创建发布、上传文件或调用外部服务。
6. 远端用户请求控制或审批。

MVP 可以先实现“事件观察 + 用户确认 + runtime 原生审批接入”。对无法稳定前置拦截的 runtime 能力，必须在 UI 和文档中明确说明限制。

### 6.8 会话与审计

会话记录应支持后续回看和远程同步。

记录内容：

1. 用户输入。
2. agent 输出。
3. runtime 类型和版本。
4. workspace。
5. 工具调用和命令摘要。
6. 文件变更摘要。
7. 审批请求、用户决策和远端参与记录。
8. 错误和取消原因。
9. 验证命令和结果。

敏感数据默认不进入可导出报告。需要记录路径或命令时，应避免保存 API Key、Token 和私钥内容。

## 7. UI / 交互需求

### 7.1 产品风格

1. 工作台优先，打开应用就能开始任务。
2. 信息密度适中，适合长时间阅读和反复操作。
3. 不做营销式 hero，不使用装饰性背景。
4. 工具调用、审批、文件变更和远程观看状态要清晰可扫描。
5. agent 差异要可理解，不把 SDK 私有术语直接暴露给普通用户。

### 7.2 主要页面

1. Agent 工作台。
2. 会话历史。
3. Workspace 管理。
4. Agent Runtime 设置。
5. 模型与供应商设置。
6. 远程连接与观看者管理。
7. 审批中心。
8. 审计日志。

## 8. MVP 范围

### 8.1 MVP 必做

1. Tauri 桌面应用骨架。
2. React 工作台 UI。
3. Python backend 流式事件接口。
4. 通用 `AcpAgentAdapter` 与 runtime descriptor。
5. Codex ACP 可运行原型。
6. Claude Code ACP descriptor、预检和实验入口。
7. opencode ACP descriptor、预检和实验入口。
8. nanobot 原型降级为 legacy 兼容 adapter，不再新增主线能力。
9. 会话存储。
10. 基础审批事件。
11. 远程只读同步观看原型。
12. 模型与 runtime 配置入口。

### 8.2 MVP 可选

1. Claude Code 可运行原型。
2. opencode 可运行原型。
3. 远端发送消息。
4. 远端处理审批。
5. 文件变更 diff 预览。
6. 多 agent 对比运行。

### 8.3 MVP 暂不做

1. 云端 IDE。
2. 多人同时编辑文件。
3. 默认跨公网中继。
4. 完整企业权限系统。
5. 对所有 runtime 的每一次文件写入提供强制前置审批承诺。

## 9. 成功指标

| 指标 | 目标 |
| --- | --- |
| 本地会话启动成功率 | >= 95% |
| 流式事件展示延迟 | <= 500ms |
| 会话恢复成功率 | >= 95% |
| Codex ACP adapter 基础任务成功率 | >= 80% |
| 远程只读同步延迟 | <= 1s |
| 远程连接撤销生效时间 | <= 3s |
| 高风险审批事件记录覆盖率 | 100% |

## 10. 主要风险

### 10.1 技术风险

1. ACP 仍在演进，不同 runtime 的实现完整度和扩展字段可能不同。
2. Codex、Claude Code、opencode 的 ACP wrapper、SDK 或 CLI 可能频繁变化。
3. 某些 runtime 的原生审批无法覆盖所有文件写入或命令执行。
4. 远程同步需要处理断线重连、事件补偿和权限撤销。
5. Windows 下进程管理、终止任务和编码问题需要额外验证。

### 10.2 产品风险

1. 用户可能误以为所有 agent 都有完全一致的能力。
2. 远程观看和远程控制的权限边界如果不清晰，会带来误操作风险。
3. 多 runtime 配置过多可能让新用户困惑。
4. 任务失败时需要把责任边界说明清楚，是模型、runtime、配置还是产品适配问题。

### 10.3 安全风险

1. 不得把 API Key、Token、私钥写入仓库或会话导出。
2. 远程连接令牌必须可撤销，不能长期明文保存。
3. 远端默认只读，控制权必须显式授权。
4. 对仓库外路径、系统目录和敏感文件访问应有明确提示。

## 11. 路线图

### Phase 1：多 Agent 工作台

1. 完成产品文档和 ACP 技术路线收口。
2. 完成通用 ACP adapter 与 runtime descriptor。
3. 接入 Codex ACP 原型，并保留 nanobot legacy adapter 作为兼容路径。
4. 完成会话存储、流式事件展示和基础审批桥接。

### Phase 2：远程只读同步

1. 建立远程 session 和连接码机制。
2. 同步会话历史和实时事件。
3. 支持断线重连和撤销连接。
4. 展示观看者列表和连接状态。

### Phase 3：Claude Code 与 opencode

1. 完成 Claude Code ACP smoke 和 descriptor 完善。
2. 完成 opencode ACP smoke 和 descriptor 完善。
3. 统一 runtime session capabilities 和 UI 选择体验。
4. 增加任务级 runtime 推荐。

### Phase 4：协作控制与安全增强

1. 支持远端发送消息。
2. 支持远端审批。
3. 增加文件 diff、审计报告和任务回放。
4. 评估跨公网中继和端到端加密方案。

## 12. 待确认问题

1. MVP 远程同步优先走局域网直连，还是直接设计中继服务？
2. 远端只读观看是否需要登录，还是使用一次性连接码即可？
3. Claude Code 和 opencode 的首个 smoke 验证范围分别到 initialize、session/new，还是真实 turn？
4. nanobot legacy adapter 的保留期限和删除条件是什么？
5. 模型配置是只作为 legacy LLM provider 管理，还是也提供 runtime 原生配置的索引入口？
6. 会话记录默认保存多久，是否需要用户手动清理？
7. 远程控制是否进入 MVP，还是只做只读观看？
